# 요청 합치기 · 같은 계산은 진행 중 한 번만

검토: 2026-09-20 · 분류: 구현 패턴 / UI·비동기 요청 / 비동기 중복 억제 패턴

별칭: Request Coalescing, Singleflight, Deduplicate In-Flight

적용 분야: 캐시 miss, 설정 조회, 동일 파일 변환, 서버 조회

## 개념과 특징

같은 키의 작업이 진행 중이면 후속 호출자가 같은 결과를 기다린다. 완료 결과를 계속 저장하는 캐시와 달리 보통 진행 중 기간만 합친다. 서로 다른 키를 한 전송에 모으는 batching과도 다르다.

## 구조와 동작

키 검사 → 진행 중이면 합류 / 없으면 단일 실행 등록 → 결과·오류 공유 → 등록 제거

## 언제 쓰고 피할까

- 사용: 동일한 비싼 조회가 동시에 몰리고 호출자별 의미·권한·결과가 정말 같을 때.
- 비추천: 같은 URL이라도 사용자·권한·본문이 다른 요청, 호출마다 부작용이 필요한 변경 작업.

## 장점과 비용

- 장점: cache stampede와 중복 원본 조회를 줄인다. 결과 계산을 여러 대기자와 공유한다.
- 단점·비용: 한 느린 작업이 모든 대기자를 붙잡고 오류도 함께 전달된다. 키 수·대기자 수·수명 상한이 없으면 메모리가 늘어난다.

## 설계·구현 가이드

1. 키를 tenant·권한·입력·버전으로 정의하고 민감 원문 대신 안전한 식별 방식을 사용한다.
2. 작업을 시작하기 전에 진행 중 map에 등록하는 원자적 경계를 확보한다. 성공·실패 모두 finally에서 자신이 등록한 항목만 지운다.
3. 한 대기자의 취소는 그 대기자만 분리한다. 다른 대기자가 남아 있는데 공통 작업을 중단하지 않는다.
4. 동시 키 수·키 길이·대기자 수·전체 deadline을 제한하고 다중 프로세스에서 로컬 map은 전역 중복을 막지 않음을 명시한다.

## 적용 예시

동일 tenant의 같은 상품 조회 100개가 동시에 miss면 조회 한 번을 공유할 수 있다. tenant를 키에서 빼면 다른 고객의 가격·권한 데이터를 섞는 버그가 된다.

이 절은 구현 결정을 설명하는 설계 사례다. 실행 프로그램이나 장비 설정 파일이 아니다.

## 실패·동시성·종료 조건

오류 결과를 map에 영구 보관하면 이후 모든 요청이 계속 실패한다. 작업이 영원히 끝나지 않을 때 deadline과 정리 책임이 필요하다. Forget 후 예전 작업이 새 등록을 지우지 않게 token을 비교한다.

## 검증 기준

동일 키 N개에서 실행 1회, 다른 키는 독립, 실패 후 새 시도 가능, 대기자 한 명 취소, key limit, 오래된 완료와 새 작업의 경합을 검사한다.
