# 유한 큐 · 생산자–소비자의 속도 조정

검토: 2026-09-20 · 분류: 구현 패턴 / 동시성·작업 분배 / 작업 전달 패턴

별칭: Bounded Queue, Producer–Consumer, SPSC, MPSC, MPMC

적용 분야: RTOS 태스크, 이벤트 처리, 서버 작업, 로그

## 개념과 특징

생산과 소비를 큐로 분리하되 개수·바이트·대기시간에 상한을 둔다. SPSC는 한 생산자/소비자, MPSC는 여러 생산자/한 소비자, MPMC는 양쪽 모두 여러 실행 주체다. 링버퍼는 큐의 저장 구현 중 하나다.

## 구조와 동작

생산 → 용량/마감 검사 → 대기 큐 → 소비자 획득 → 처리 → 자원 반환

## 언제 쓰고 피할까

- 사용: 개별 이벤트를 보존해야 하고 짧은 burst를 흡수하거나 실행 문맥을 분리할 때.
- 비추천: 항상 최신값만 필요한 제어 목표, 호출 즉시 결과가 필요한 짧은 연산, 처리 능력보다 영구적으로 큰 입력을 숨기려는 경우.

## 장점과 비용

- 장점: 실행 문맥과 순간 속도를 분리한다. admission 제어와 점유율 관측 지점을 만들기 쉽다.
- 단점·비용: 적체는 지연이다. 큐를 크게 하면 메모리와 오래된 작업이 늘어난다. 다중 워커에서는 dequeue 순서와 완료 순서가 다르다.

## 설계·구현 가이드

1. 메시지 크기·최대 개수·총 바이트와 소유권을 정한다. 포인터 큐는 payload 메모리까지 별도 한도를 둔다.
2. full 시 거절, 시간 제한 대기, drop-oldest 중 업무 의미에 맞춰 고른다. ISR은 기다리지 않고 전용 안전 API를 쓴다.
3. 우선순위와 공유 자원 락 범위를 정한다. 소비자에게 필요한 락을 가진 채 enqueue 대기하지 않는다.
4. 종료 상태에서 새 입력을 막고 drain 또는 cancel을 선택한다. 빈 큐 종료와 처리 중 작업 종료를 구분한다.

## 적용 예시

최대 32개의 64-byte 이벤트는 payload만 2048 byte다. 큐 관리 정보·정렬·태스크 스택은 별도다. 초당 100건, 건당 20 ms 소비 한 개면 처리율은 50건/s라 어떤 유한 큐도 지속 입력을 보존하지 못한다.

이 절은 구현 결정을 설명하는 설계 사례다. 실행 프로그램이나 장비 설정 파일이 아니다.

## 실패·동시성·종료 조건

큐 가득 참을 무시하면 조용한 유실이 생긴다. Zephyr message queue는 복사 기반이며 큰 항목의 복사 시간이 인터럽트 지연에 영향을 줄 수 있다. 큐 대기와 처리 실패는 다른 지표다.

## 검증 기준

용량+1 입력, timeout, 생산자 경합, 우선순위 역전, 종료 중 대기를 검사한다. 수락=완료+실패+대기+실행 중이라는 회계가 맞아야 한다.
