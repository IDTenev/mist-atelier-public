# 더블 버퍼 · 읽기와 쓰기의 작업장 분리

검토: 2026-09-20 · 분류: 구현 패턴 / 버퍼·데이터 이동 / 버퍼 소유권 패턴

별칭: Double Buffer, Ping-Pong Buffer, 이중 버퍼

적용 분야: 디스플레이, ADC 블록, 오디오, 영상 프레임

## 개념과 특징

한 버퍼를 소비하는 동안 다른 버퍼를 생산한다. 완성된 시점에 역할을 교환한다. 최신 완성 화면을 교체하는 방식과 모든 블록을 번갈아 처리하는 ping-pong은 유실 정책이 같지 않다.

## 구조와 동작

A: 채우기 / B: 소비 → A 완료 표시 → B 소비 완료 확인 → 경계에서 역할 교환

## 언제 쓰고 피할까

- 사용: 고정 크기 블록의 생산과 소비를 겹칠 수 있고, 각 단계의 최장 시간이 다음 블록 준비 시간 안에 들어올 때.
- 비추천: 소비 시간 편차가 크거나 블록을 하나도 버릴 수 없는데 소비가 늦는 경우. 유한 큐나 더 많은 슬롯과 역압력이 필요하다.

## 장점과 비용

- 장점: 읽는 중인 화면/블록을 수정하지 않는 소유권 규칙이 명료하다. 하드웨어 전송과 CPU 계산을 겹칠 수 있다.
- 단점·비용: 단일 버퍼의 약 두 배 RAM이 필요하고 완성 경계까지 지연이 생긴다. 두 버퍼만으로 끊김·tearing 방지가 자동 해결되지 않는다.

## 설계·구현 가이드

1. 각 버퍼를 FREE, FILLING, READY, READING 상태로 관리하고 한 시점에 하나의 쓰기 소유자만 허용한다.
2. 스왑은 소비 완료/디스플레이 VSYNC 등 실제 장치 경계와 맞춘다. 포인터 교환의 원자성과 메모리 순서를 확인한다.
3. 블록 처리 마감과 late 정책을 정한다. 모든 샘플 필요 시 재사용 금지·오류 처리, 화면 최신값이면 이전 READY 프레임 폐기를 명시한다.
4. DMA 송신 완료 전에 flush 완료를 알리지 않는다. 캐시·정렬·장치가 접근 가능한 메모리를 점검한다.

## 적용 예시

48 kHz 오디오 480샘플 블록은 10 ms 간격이다. 한 블록 처리+스케줄링 최악 시간이 10 ms를 넘으면 단순 ping-pong으로 지속 입력을 보존할 수 없다. 평균 2 ms만 보고 통과시키지 않는다.

이 절은 구현 결정을 설명하는 설계 사례다. 실행 프로그램이나 장비 설정 파일이 아니다.

## 실패·동시성·종료 조건

생산자가 READING 슬롯을 재사용하면 찢어진 데이터가 된다. STOP은 새 전송을 막고 진행 중 DMA의 완료 또는 안전한 취소를 확인한 뒤 메모리를 반환한다.

## 검증 기준

소비 완료를 한 블록 이상 지연시켜 overrun 정책을 확인한다. 블록 세대 번호로 혼합·중복·누락을 검출하고 화면은 VSYNC 전후 전환을 관찰한다.
